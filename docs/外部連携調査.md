# 外部連携の調査・採用方針

確認日：2026年11月14日。料金・上限は将来変わるため、運用開始時は各管理画面の実際の割当を優先してください。

## YouTube

公式プロフィール掲載のチャンネルIDを採用し、172人全員に登録しました。Wikiで取得できた34人のうち27人のページで同一IDの文字列を確認しました。未一致は誤りとは断定せず、APIでのチャンネル本人性検証済みとは扱っていません。

本実装は `channels.list` → uploads playlist → `playlistItems.list` → `videos.list` の順で新着を取得します。30分更新では既知のlive/upcoming IDを一括照会し、順番に `search.list` を呼んで新しい枠を追加します。開始時刻だけで配信中と推定せず、APIの実開始・実終了時刻とliveBroadcastContentを利用します。

確認時点の公式資料では、Search Queriesは独立した枠で既定100呼出/日、その他のAPIは合計10,000 units/日です。channels/playlistItems/videosのlistは各1 unit。Searchを従来の「100 units/回」として通常枠に合算せず、別カウンターで管理しています。日付境界は米国太平洋時間です。[公式クォータ表](https://developers.google.com/youtube/data/determine_quota_cost)、[Search仕様](https://developers.google.com/youtube/data/reference/rest/v3/search/list)

172人・各10件の場合、新着一巡の目安はchannels約4回＋playlistItems172回＋videos約35回＝約211 units、1日2回で約422 unitsです。既知配信の状態確認分は別途加算されます。検索既定値は1人×2検索×48回＝96検索/日です。通常枠9,000、検索96をローカル上限としていますが、他用途・手動実行・キャッシュ消失もあるためGoogle側の残量も確認が必要です。

削除・非公開で応答に返らない動画は取り除きます。29日以上再確認できていない動画は次の同期で除外し、画面でも表示しません。同期自体を長期間止める場合は、公開済みJSONやActionsキャッシュに残るAPIデータも管理者が消去してください。配信状態が1時間以上古い場合とオフライン時は「最終確認時」の表示に切り替えます。[YouTube開発者ポリシー](https://developers.google.com/youtube/terms/developer-policies)

公開情報だけを扱うため視聴者のYouTubeログインやOAuthは不要です。APIキーはActionsの環境にだけ渡し、公開JSONやViteに渡しません。API失敗時のログにもリクエストURL・キーを出しません。実APIは未実行であり、モックによる結合テストで動作を確認しました。

参照：[playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list)、[videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list)

## X / Twitter

| 方法 | 調査結果 | 本版での扱い |
|---|---|---|
| 公式アカウントリンク | キー不要。公式プロフィールから取得可能 | 172人に実装。Wiki取得34人ではアカウント名の一致も確認 |
| 公式タイムライン埋め込み | 公開アカウント向けの公式ウィジェットが案内されている。第三者スクリプトや通信が増え、ブラウザー環境によって表示に差が出る | iPhoneの軽さと確実なリンク遷移を優先し、本版には追加しない |
| X API | 公式資料は前払いクレジットによる従量課金。開発者登録・認証・利用可能な読み取りAPI・残高・レート上限の確認が必要 | キーも課金承認もないため呼び出さない。無料で全員分の投稿取得ができるとは案内しない |

XのHTMLスクレイピング、ログインの迂回、非公式ミラーや代理取得は実装していません。リンクの根拠は公式プロフィールの掲載先で、XへのAPI照会・投稿内容の確認を意味しません。

参照：[X公式料金説明](https://docs.x.com/x-api/getting-started/pricing)、[X公式埋め込み説明](https://help.x.com/en/using-x/embed-x-feed)、[公式埋め込み作成画面](https://publish.x.com/)

## GitHub Actions

ワークフローは既定ブランチ上で実行します。cronの時刻はUTCです。GitHubは定期実行の遅延・混雑時の省略、公開リポジトリが長期間更新されない場合のスケジュール無効化を説明しています。30分は厳密な時刻保証ではありません。[公式スケジュール説明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

ワークフローの `contents` 権限はreadのみです。更新JSONはキャッシュを経由してPagesの成果物に含め、リポジトリに自動コミットしません。API同期失敗はStep Summaryと公開JSONのエラー情報に残し、プロフィール公開を継続します。
