## 2. YouTubeの自動更新を有効にする

1. 自分のGoogle Cloudプロジェクトで **YouTube Data API v3** を有効にし、APIキーを作成します。キーのAPI制限はYouTube Data API v3に限定してください。ブラウザー用のHTTPリファラー制限を設定したキーはGitHub Actionsでは使えません。
2. GitHubリポジトリの Settings → Secrets and variables → Actions → New repository secret に次を登録します。`VITE_` 付き変数やソースコードには入れません。

| Secret名 | 値・省略時 |
|---|---|
| `YOUTUBE_API_KEY` | 自分のAPIキー。必須 |
| `YOUTUBE_DAILY_UNITS` | `9000`。通常API用の1日上限。Google側の割当以下に設定 |
| `YOUTUBE_DAILY_SEARCH_CALLS` | `96`。Search Queries用の1日呼出上限。`0`なら新規配信枠検索なし |
| `YOUTUBE_SEARCH_CHANNELS_PER_RUN` | `1`。30分実行で検索する人数。1人につきlive/upcomingの2呼出 |

3. Actionsで上記ワークフロー → Run workflow → `youtube_mode: full` を一度実行します。成功後、プロフィールの「動画の最終取得」に時刻が入ることを確認します。
4. 定期実行は新着が **日本時間09:17 / 21:17**、取得済み配信状態が **毎時07分 / 37分**。Actionsの混雑で遅延・省略されることがあります。iPhoneが閉じていてもサーバー側で実行します。
5. APIに失敗してもプロフィール公開は継続し、前回データ・確認時刻・エラー表示を保持します。ActionsのSummaryとUpdate YouTubeのログを確認してください。Pagesの成功だけではAPI取得成功を意味しません。

API取得結果はActionsキャッシュと公開用JSONに保持し、リポジトリへの自動コミットは行いません。公開データにはキーを含めません。キャッシュ消失時は取得履歴・検索順序・ローカルの使用量カウンターがリセットされます。使用量の最終的な上限はGoogle Cloud側でも設定・確認してください。他のアプリと同じキー・プロジェクトを共有する場合、その使用量はこのカウンターには入りません。

### 配信予定の網羅性について

新着は各チャンネルのアップロード一覧先頭10件を12時間ごとに取得します。配信予定はアップロード一覧に必ず含まれるとは限らないため、30分ごとに1人ずつ公式検索APIでlive/upcomingを探します。172人では一巡まで約3.6日かかり、短時間だけ公開される枠や突発配信は見逃します。**全172人の新しい配信枠を30分以内に発見する機能ではありません。** 取得済みの配信枠は30分ごとに状態確認します。必要ならGoogleに検索上限の増加を申請し、実際の割当の範囲でSecretを調整してください。上限回避のための複数キー分散は実装していません。

各APIは1ページのみ取得します。50件を超える同時配信予定、12時間に10件を超える投稿、非公開・メンバー限定・削除済みの動画は網羅しません。Shortsの推測分類は行いません。APIで返らなくなった取得済み動画は次の照会で除外します。公開画面は最大5件です。

## 4. パソコンでの検証
